How we work

We build Techlog using Techlog.

Techlog exists because we want engineering history to be easier to trust. So we hold ourselves to it: our own bugs, proposals, decisions, releases, and incidents are recorded as Techlog events, linked to each other, and kept with their evidence.

Every change to Techlog has a story, and we keep ours in Techlog. When something goes wrong, we want to follow it back to the decision that shaped it, in the same way we hope you will one day follow yours.

Try it now

Run the server on your machine

A basic Techlog server runs locally: an event API, MCP tools for AI agents, and a read-only web UI, in one program. It has no authentication and no signatures, so keep it on your own machine or a trusted network. It is not the platform that is coming soon.

From the root of the repository, with Go 1.27 or later and make installed:

{{code bash getting-started/run-server.sh}}

Open http://localhost:8080 to browse the example story in the UI. To let Claude record and read events, connect it to the same server:

{{code bash mcp-connect.sh}}
