How it works

An agent reports progress. Techlog connects it.

API first: every step is a call, and the website is just another client.

  1. 1

    Agent sends

    An MCP request: techlog_record_event.

  2. 2

    Techlog reviews

    Checks the event against the schema and its evidence.

  3. 3

    Finds connections

    Links it to the problem, decision, tests, and release.

  4. 4

    Stores, serves

    One event store, read by API, MCP, and the UI.

Open standard · draft 0.1

The event is plain JSON.

Any agent or tool can write it, and any tool can read it. A small required core, typed links marked confirmed or hypothesis, and a record of who produced it. Below, a techlog_record_event call with the ids of the example story, abridged to the fields that matter.
