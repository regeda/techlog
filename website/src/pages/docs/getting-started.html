Getting Started

Runs locallyDraft 0.1

Install

Install the latest released binary for Linux or macOS (amd64 or arm64). The installer puts techlog in $HOME/.local/bin and checks the download against the release's checksums.txt first. The source, the README and the releases are in the GitHub repository; its README covers flags and building from source.

{{code bash getting-started/install-binary.sh}}

Demo

Load the Spring Spin example story and start the server.

{{code bash getting-started/demo-server.sh}}

The web UI

The UI is now at http://localhost:8080/. It is read-only: it never writes an event.

  • Events at /: a table of events, newest first, 50 per page with Previous and Next links. Filter by text, system, type, and date range; every view is a plain URL you can share.
  • Event at /events/{id}: all fields, the links that leave the event and the links that point at it, sources, evidence, and the raw JSON. A hypothesis link is drawn dashed.
  • System at /systems/{system}: a timeline of the latest events of one system.
  • Story at /story/{id}: the events connected to one event through links, oldest first, with each event's relations. It lets you follow a story like the one the home page animation shows.

The server has no authentication, so keep it on localhost or a trusted network.

A first event

This is the smallest valid event. Every field here is required. The idempotency_key is yours to choose: reuse it when you retry, and the server rejects the repeat. The event model explains each one. When you submit an event, leave out the id: the server assigns it, and ignores one you send. time and schema_version may also be left out; the server fills them in.

What the call does

MethodPathPurpose
POST/api/v1/eventsRecord an event. The server validates it, assigns the id, and returns the stored event as {"event": {...}} with status 201.

An invalid event gets status 422 and a list of problems, each with the JSON Pointer path of the field to fix. Evidence is recorded inside the event, as references; there is no separate evidence endpoint. The full list of routes is on HTTP API.
