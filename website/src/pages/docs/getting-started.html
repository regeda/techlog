Getting Started

Proposed · draft 0.1Illustrative examples

Illustrative API. The calls below show the proposed shape of the Techlog API. No hosted endpoint exists, and techlog.example.invalid is a reserved name that cannot resolve. Running these samples as-is will fail by design. They also omit the event signature that the proposed API requires by default; see signed events.

What you will do

  1. Record a proposal that is linked to the problem that motivated it.
  2. Attach the test report as evidence.
  3. Read the recent history of the system.

The samples use the Spring Spin story: a service called promo-api and a discount game for new clients.

What the calls do

MethodPathPurpose
POST/v0/eventsRecord an event. The recorder assigns the id and returns it.
POST/v0/events/{id}/evidenceAttach an evidence reference to an event.
GET/v0/systems/{system}/historyRead the recent events of one system.

Every call sends Authorization: Bearer $TECHLOG_TOKEN.
