Claude plugin

Implemented · basicDraft 0.1

What it does

A development plugin, such as superpowers, runs the engineering workflow: it asks the questions, designs the change and writes the plan. The techlog plugin sits on top of it. Each Techlog skill hands the thinking to a skill of the development plugin, adds context from Techlog and the repository, asks you to confirm, and records the event. Nothing is recorded that you have not seen and confirmed.

Install

Connect the server first (see MCP integration), then install the plugin straight from the GitHub repository with the two commands in Claude Code. /techlog:welcome explains the rest and answers questions about the setup.

{{code bash claude-plugin-install.sh}}

The skills

SkillWhat it doesRecords
/techlog:problemNarrows a problem with a decision tree, shows a draft, and records it after you confirm. Asking Claude to "create a Jira ticket" or "log a bug" starts it. It never creates a Jira ticket; a Jira key you give becomes evidence.problem.reported
/techlog:proposalFinds the problem in Techlog, collects context for you to confirm, runs the design process of the development plugin, and records the result linked to the problem.proposal.recorded
/techlog:welcomeA help desk: answers questions, shows the status, and switches the development plugin with /techlog:welcome use <plugin>.Nothing
/techlog:recordThe only skill that writes events. The others call it. It also answers "what happened to this system earlier?".Any event type

The journey

We are all problem solvers. Start with /techlog:problem, and use /techlog:record wherever you want to record a step. With superpowers as the development plugin:

  1. Problem. /techlog:problem runs superpowers:brainstorming with a decision tree to narrow it. You confirm the draft and Techlog records problem.reported. Stage: problem.
  2. Proposal. /techlog:proposal confirms a context note, then brainstorming designs the change and writes the spec. Techlog records proposal.recorded with the spec as evidence. Stage: proposal.
  3. Decision. When you ask to plan, Claude stops before superpowers:writing-plans, shows a draft decision.made with the spec as evidence, and records it once you say yes. Stage: decision.
  4. Everything after. Implementation, verification, release and incidents have no skill yet. Record them with /techlog:record: change.implemented, verification.completed, release.deployed and the rest.

Each event links back to the one before it, so anyone can walk the story from the problem to its follow-up.
